# Genealogy Tech Watch — Линии времени

Каталог проектов цифровой генеалогии и датированный исследовательский дайджест.

## Безопасный режим публикации

- **GitHub Actions не используются**: в репозитории отсутствует `.github/workflows/`.
- Статический GitHub Pages публикуется из `main` / `docs`.
- Никаких сборок, Docker, артефактов или Actions cache.
- `docs/index.html` — каталог; `docs/digest.html` — дайджест.
- `catalog.json`, `digest.json` — исходные экспортные снимки данных. Страницы содержат встроенные копии данных и работают офлайн.

## Локальный запуск и проверки

Конвейер использует стандартную библиотеку Python. Проверки интерфейса требуют Node.js.
Сетевого опроса, установки зависимостей и автоматического push в командах нет.

```powershell
Set-Location D:\AI\genealogy-tech-watch-git
python tools/watch_pipeline.py validate
python -m unittest discover -s tests -v
node tests/ui_smoke.cjs
python -m http.server 8000 --bind 127.0.0.1
```

Откройте `http://127.0.0.1:8000/docs/index.html`. Каталог и дайджест содержат seed;
подробные исследования читают опубликованные JSON через HTTP. Каталог и дайджест
не подменяются сохранёнными в браузере импортами.

Публикация: в GitHub **Settings → Pages → Deploy from a branch → main → /docs**.
Адрес: `https://linesoftime.github.io/genealogy-tech-watch/`.

**Примечание:** GitHub Pages может использовать внутренний механизм развёртывания GitHub. Выбор «Deploy from a branch» не создаёт нашего собственного workflow, но не гарантирует абсолютно нулевых внутренних записей о публикации. Проверяйте Billing → Actions.

## Как обновлять

1. Добавьте находку с первоисточниками в `data/discoveries.jsonl`. Неизвестные сведения
   укажите явно; авторские заявления отделите от независимого испытания.
2. Запустите сравнение локальных кандидатов (это не сетевой поиск):

   ```powershell
   python tools/watch_pipeline.py scan --dry-run
   python tools/watch_pipeline.py review --report
   ```

3. Человек проверяет новизну, значимость, источники и дельту. Для утверждённой записи
   заполняются reviewer, reviewed_at, review_status и reviewed_content_hash из отчёта.
4. Подготовьте план; дату выпуска задайте явно:

   ```powershell
   python tools/watch_pipeline.py apply --approved-only --edition-date 2026-10-22 --dry-run
   # После просмотра diff подставьте plan_hash:
   python tools/watch_pipeline.py apply --approved-only --edition-date 2026-10-22 --write --expect-plan HASH
   ```

5. Повторите проверки. Apply сохраняет историю и синхронизирует JSON/seed; повторный
   запуск не создаёт дублей. research_only обновляет карточку без выпуска дайджеста.
   `--input` сохраняет применённые утверждённые записи и в основной журнал.
6. Для ручных изменений JSON используйте `python tools/sync_data.py`. Старые
   исследовательские поля меняйте только по подтверждённым источникам.
7. Перед публикацией просмотрите тесты, изменения и состав коммита. Добавляйте файлы
   адресно: резервные файлы и чужие скрипты не должны попасть в коммит. Push — только
   по явному разрешению; ни один инструмент конвейера его не выполняет.

Подробности: [журнал и проверка](DISCOVERY_WORKFLOW.md), [apply](APPLY_WORKFLOW.md),
[интерфейс и миграция](INTERFACE_REVIEW.md), [фактическое применение](LOCAL_APPLY_REVIEW.md).

## Источники и ограничения

Содержимое основано на прежних исследовательских обзорах; не является независимым
повторным аудитом всех репозиториев. Новые утверждённые события имеют собственные
источники и статусы. Лицензии и заявления о возможностях требуют проверки.
«Применимость для России» извлечена из исходного путеводителя с сохранением строки
и её происхождения; доступность сервисов из РФ отдельно не проверена.

Исторические данные после первого локального применения: 164 проекта, 142 расширенных
исследования, 19 событий в 5 выпусках. 308 предупреждений о старых редакционных
пробелах сохранены для ручного рассмотрения. Автоматизация этапа F не включена.
