# Genealogy Tech Watch — Линии времени

**Исследовательский каталог открытых инструментов цифровой генеалогии, архивных технологий и ИИ** с датированным дайджестом изменений. Он помогает выбрать решения для исследования источников, обработки исторических документов и разработки генеалогических систем.

**[Открыть каталог](https://linesoftime.github.io/genealogy-tech-watch/)** · [Дайджест](https://linesoftime.github.io/genealogy-tech-watch/digest.html) · [Подобрать по задаче](https://linesoftime.github.io/genealogy-tech-watch/tasks.html) · [Лицензии](https://linesoftime.github.io/genealogy-tech-watch/licenses.html) · [Приоритеты](https://linesoftime.github.io/genealogy-tech-watch/priorities.html)

## Что можно найти

- Генеалогические программы, GEDCOM, семейные деревья, источники и доказательства.
- OCR/HTR, индексация рукописных документов, цифровые архивы и IIIF.
- Исторические места, приходы, административно-территориальные изменения и геоданные.
- Сопоставление персон и записей, исследовательские рабочие места, AI-агенты, API/MCP.
- Инструменты смежных областей: digital humanities, knowledge graphs, GLAM и исторические исследования.

Каталог поддерживает поиск, фильтры по направлению, редакционному приоритету и применимости для России, карточки с ограничениями и лицензиями, расширенные исследования и подбор по задаче. Статические страницы содержат встроенные данные для автономного просмотра; отдельные подробные материалы и внешние ссылки могут требовать сеть.

## Состояние данных и ограничения

**Снимок по объединённому [PR #2](https://github.com/LinesOfTime/genealogy-tech-watch/pull/2), 24 октября 2026:** 169 карточек, 149 расширенных исследований, 30 событий в 7 выпусках. Эти числа — состояние конкретного обновления, а не автоматически обновляемый счётчик README; текущие значения отображаются на сайте и в опубликованных JSON.

Каталог объединяет ранее подготовленные исследования и новые проверенные события. **Дата выпуска не означает повторную проверку всех репозиториев.** Для исторических карточек полнота и актуальность сведений различаются. Существование проекта, сведения из README, заявления авторов, статическая проверка исходников и независимое испытание — разные уровни доказательности.

«Применимость для России» — редакционная оценка по назначению и материалам проекта; она **не подтверждает** доступность сервиса из РФ, качество распознавания русских рукописей или поддержку исторической административной географии. Приоритеты P1–P3 выражают практическую значимость для исследовательской платформы, а не качество или популярность проекта. Неизвестные лицензии и характеристики не следует считать подтверждёнными.

## Как обновляется каталог

1. Находка фиксируется в `data/discoveries.jsonl` с первоисточниками, датой, сравнением с прежним состоянием, лицензией и оговорками.
2. Локальные `scan` и `review` проверяют структуру, дубликаты и готовность к применению. **Они не ищут проекты в интернете** и не проверяют истинность внешних ссылок.
3. После проверки источников Codex или исследователь готовит пакет. Пользователь утверждает его целиком или с исключениями; до этого события остаются `pending`.
4. Для утверждённого пакета `apply` строит план, проверяет его хеш и согласованно обновляет каталог, исследования, дайджест, опубликованные JSON и встроенные HTML-данные.
5. Перед публикацией выполняются проверки целостности, тесты и просмотр изменений. **Публикация в GitHub не происходит автоматически от запуска конвейера.**

## Локальный запуск

Нужен Python со стандартной библиотекой; для UI smoke-тестов — Node.js. Команды ниже не устанавливают зависимости и не выполняют push:

```powershell
Set-Location D:\AI\genealogy-tech-watch-git
python tools/watch_pipeline.py validate
python -m unittest discover -s tests -v
node tests/ui_smoke.cjs
python -m http.server 8000 --bind 127.0.0.1
```

Откройте `http://127.0.0.1:8000/docs/index.html`.

Для нового выпуска (после проверки и утверждения конкретных событий):

```powershell
python tools/watch_pipeline.py scan --dry-run
python tools/watch_pipeline.py review --report
python tools/watch_pipeline.py apply --approved-only --edition-date YYYY-MM-DD --dry-run
# После проверки плана и его фактического plan_hash:
python tools/watch_pipeline.py apply --approved-only --edition-date YYYY-MM-DD --write --expect-plan HASH
python tools/watch_pipeline.py validate
```

`YYYY-MM-DD` и `HASH` — заполняемые значения, а не буквальные аргументы. Ручные изменения JSON синхронизируются командой `python tools/sync_data.py`. Не обходите проверку хеша и не проставляйте утверждение без решения по конкретному пакету.

## Публикация и ограничения инфраструктуры

Сайт размещается через GitHub Pages из `main` / `docs`. В репозитории не используется собственный GitHub Actions workflow (`.github/workflows/` отсутствует); это не исключает внутренние операции GitHub Pages и их учёт в Billing. Сборки Docker, Actions artifacts и cache для обновления каталога не требуются.

Внешний мониторинг GitHub и уведомления о находках не запускаются локальными командами `watch_pipeline.py`. Отдельную автоматизацию мониторинга не следует считать включённой без подтверждения её расписания и работы.

**Лицензии сторонних проектов принадлежат их правообладателям.** Перед повторным использованием кода проверяйте лицензию конкретной версии и совместимость условий.
