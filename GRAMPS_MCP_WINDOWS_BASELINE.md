# G-MCP-01: первый фактический запуск на Windows

**Цель:** создать воспроизводимую изолированную среду Gramps Web для Gramps MCP и выполнить upstream-интеграционные тесты. Это подготовительный этап, **не** выполнение сценариев T1–T7 и не независимое E3/E4.

## Проверенная исходная версия (срез 2026-11-09)

- Зеркало: https://github.com/Genealogy-MCP/gramps-mcp
- Коммит: `9ce862da7543ce09ef7683330fce049b1c7ff24b` (из GitHub API; основной upstream — GitLab)
- `pyproject.toml`: версия 3.15.27
- `docker-compose.test.yml`: Gramps Web 26.10.2 (образ с SHA256), Redis, PostgreSQL, Celery и тестовые тома
- `tests/fixtures/seed.gramps`: опубликованная fixture upstream (418644 байта на момент сверки)
- Makefile поддерживает `docker-up`, `docker-seed`, `test-unit`, тестовую группу integration.

Не используем `docker-compose.yml` с `latest` для воспроизводимого эксперимента и не подключаем основное дерево.

## Предпосылки

Windows 11 с Docker Desktop (запущенным Linux Engine), Git и `uv` (Python package manager). Команды должны быть доступны из PowerShell. Docker Desktop должен иметь достаточный запас памяти и диска. При отсутствии любой зависимости скрипт завершится ошибкой, не маскируя её успешным результатом.

## Одно действие из корня репозитория

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\run_gramps_baseline.ps1
```

Скрипт создаёт отдельную папку `local-gramps-baseline`, загружает исходный код upstream, переключается на **проверенный SHA**, устанавливает зависимости по lock-файлу, поднимает тестовый Gramps Web в отдельном Docker Compose-проекте с уникальным именем вида `gtw-gramps-<12 символов>`. Скрипт также выставляет уникальный `COMPOSE_PROJECT_NAME` для дочерних Python-процессов, запрещает пропуск интеграционных тестов через `REQUIRE_INTEGRATION=1` и очищает унаследованные `GRAMPS_API_URL` и учётные данные, чтобы не попасть в действующее дерево, засевает fixture и запускает `pytest -m integration --no-cov -q`.

Результаты: `local-gramps-baseline/logs/baseline-*.txt` и `baseline-*-metadata.json` с точным именем Compose-проекта. Каждый запуск получает новые тестовые тома; старые тома не затрагиваются и требуют отдельной очистки по сохранённому имени проекта. Они не являются доказательством независимости испытания. **Никакая запись в `docs/trials.json` не добавляется автоматически.**

Для удаления тестовых томов **в рамках этого же запуска**:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\run_gramps_baseline.ps1 -CleanupTestVolumes
```

Внимание: `-CleanupTestVolumes` вызывает `docker compose ... down -v` и уничтожает данные **только автоматически созданного Compose-проекта текущего прогона**. Без ключа контейнеры и тома сохраняются для изучения. Повторный запуск с ключом создаст новый отдельный проект и очистит только его, а не предыдущие. Для уборки старого прогона используйте сохранённое имя проекта и команду `docker compose -p <имя> -f docker-compose.test.yml down -v` внутри его checkout, предварительно проверив имена томов.

## Следующая стадия

**Обязательное условие безопасности:** baseline запускается только на тестовой инфраструктуре upstream. Переменные для подключения к пользовательскому Gramps Web игнорируются; данные рабочего дерева не используются. При незапущенной тестовой среде интеграционные тесты должны завершиться ошибкой, а не сообщением об успешной проверке.

После успешного baseline — выполнить собственный протокол [G-MCP-01](PILOT_GRAMPS_MCP_01.md) T1–T7: чтение записей/цитирований, негативные ID, сравнение с Web API, отдельная проверка прав записи и фиксация снимков до/после. Для фиксации наблюдений предусмотрен [анализатор](GRAMPS_MCP_CAPTURE_RUNNER.md).

**Ограничения:** этот PowerShell-скрипт подготовлен для запуска пользователем на Windows, здесь не выполнялся. В текущем исполняющем окружении Docker отсутствует. Совместимость upstream-тестов с вашим компьютером до их запуска не подтверждена.
