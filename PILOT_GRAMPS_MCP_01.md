# Пилот G-MCP-01: проверка чтения источников и цитирований через Gramps MCP

**Статус: ПЛАН, НЕ ИСПЫТАНИЕ.** Дата подготовки: 2026-11-09.
Целевой объект каталога: `genealogy-mcp/gramps-mcp`.
Редакционный приоритет: «Не оценён»; практический: P2 (утверждён ранее).
Доказательность: E1 по материалам автора. Ни E3, ни независимый результат этим планом не присваиваются.

## Задача
Проверить, сможет ли исследовательский кабинет через MCP:
- прочитать заранее известное лицо, связанное событие, источник и цитирование;
- вернуть идентификаторы исходных записей, не создавая вымышленных утверждений;
- не изменять данные во время запросов чтения;
- воспроизвести те же результаты прямыми запросами к Gramps Web API.

Не включать редактирование, создание или удаление записей до отдельного утверждённого сценария. Не подключаться к основному дереву.

## Точный объект испытания
Перед запуском обязательно зафиксировать URL исходного репозитория, Git commit SHA,
версию Gramps Web и API, версию Gramps MCP, перечень реально доступных MCP-инструментов
и их входные параметры. **Не применять команды по памяти:** доступные инструменты
и ограничения могут различаться между форками и релизами.

Идентичные названия у `genealogy-mcp/gramps-mcp`, `cabout-me/gramps-mcp`,
`knuckles-team/gramps-mcp` и `gramps-mcp-dotnet` не делают их одной реализацией.
Подмена проекта при проверке запрещена.

## Предпосылки и безопасная среда
1. Изолированный Gramps Web с отдельной базой / копией, без связи с рабочим деревом.
2. Локальный защищённый MCP-транспорт с ограниченными правами учётной записи.
3. По возможности строго read-only учётная запись. Проверить доступы непосредственно,
   а не считать, что текст запроса «ничего не меняй» технически запрещает запись.
4. Сделать резервную копию **включая медиа отдельно**, если MCP backup их не охватывает.
   Проверку полноценного восстановления проводить вне MCP.
5. Сохранить хэши исходных данных и/или экспортированный снимок дерева до теста и после.
6. Использовать только синтетическое дерево, не публиковать персональные данные живущих.

## Минимальный синтетический эталон
Создать в тестовом дереве три искусственные записи о взрослых вымышленных лицах,
две записи событий, один источник и два цитирования. Пример имён не является
историческим фактом; ID и handles фиксируются после импорта.

- A: условное лицо, 1880 г. р.; B: условный родитель; C: условный супруг.
- События: рождение A (1880), брак A и C (1902).
- Источник S1: вымышленная метрическая книга; цитирования C1 и C2 с различными
  условными листами. Требуется эталонная таблица `person_id / event_id / source_id /
  citation_id / expected_relation`.
- Никаких реальных архивных шифров или ложных ссылок на архивы в фикстуре.

## Проверки и измерения
| № | Сценарий | Результат | Метрика |
|---|---|---|---|
| T1 | Получить A по известному ID | Правильное лицо, без подмены B/C | точные совпадения ID / число запросов |
| T2 | Получить событие рождения A | Дата и связанный ID совпадают | точные совпадения полей / все проверенные поля |
| T3 | Проследить связь событие → цитирование → источник | Все связи совпадают с эталоном | правильные связи / всего эталонных связей |
| T4 | Запросить неизвестный ID | Явный «не найдено» без выдуманной записи | корректные отказы / число негативных тестов |
| T5 | Сопоставить чтение через MCP и прямой API | Совпадают нормализованные значения и ID | совпавшие поля / все сопоставленные поля |
| T6 | Сравнить состояние дерева до и после чтения | Никаких незаявленных изменений | число изменённых записей |
| T7 | Отказ доступа к операциям записи | Запись запрещена фактическими правами | запрещённые операции / число проб |

Тест T7 проводить только на отдельной тестовой базе; запрет подтверждать протоколом
авторизации или контролируемым вызовом, не полагаясь на текстовое обещание модели.

## Протокол
Для каждой операции сохранять: номер, UTC timestamp, версию/commit, параметры
(без секретов), фактический сырой ответ, нормализованный результат, эталон,
статус pass/fail, ошибку и замечания. Секреты и персональные данные редактировать
перед публикацией. Указывать число вызовов, число ошибок и длительность
измерений, если они действительно выполнены.

**Критерий первого пилота:** T1–T6 проходят без необъяснённых различий,
T7 подтверждает фактические ограничения записи, восстановление копии возможно.
До этого решение не объявляется подходящим для эксплуатационного дерева.

## Что не сделано
В этом изменении Gramps MCP не устанавливался, тестовые записи не создавались,
API не вызывался, числовые результаты не измерялись. `docs/trials.json`
остаётся пустым. Выполнение возможно только на отдельно подготовленном
тестовом Gramps Web и с зафиксированной версией инструмента.
