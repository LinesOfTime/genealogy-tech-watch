# Исправление содержимого карточки OpenRefine и редакционных блоков

Обнаружено: use_case и editorial_use_case OpenRefine пусты; identical audit_notes
и catalog.limitations содержат описание возможностей и маркер редакционного долга.
Рендерер выводил эту заметку дважды как ограничения, а назначение — как «Программа».

Содержание OpenRefine уточнено по официальным источникам:

- https://openrefine.org/ — очистка, преобразование, кластеризация и reconciliation;
- https://openrefine.org/docs/manual/cellediting#cluster-and-edit — похожие значения
  и ручное подтверждение предложенных изменений;
- https://openrefine.org/docs/manual/reconciling — работа с внешними reconciliation-сервисами.

Добавлены понятное назначение, редакционный пример подготовки архивной таблицы и
ограничения. Работа с генеалогическими данными не объявляется независимо испытанной.
Кластеризация не приравнивается к доказанному тождеству людей; качество на российских
источниках и доступность внешних сервисов не подтверждаются. Лицензия, приоритет,
тип, исходный guide_excerpt, audit_notes и прежняя история не менялись.

Изменённые поля сохранены в editorial_corrections вместе со старыми значениями,
датой и источниками как в каталоге, так и в исследовании. Это исправление описания,
а не новое технологическое событие: выпуск дайджеста не создаётся.
Каталог, docs-копия и seed синхронизированы; производный подбор задач пересобран.

Общее исправление отображения:

- применение: editorial_use_case → catalog.use_case → строка «Возможности / сценарий:»;
  используется содержательный текст, исходные оговорки сохраняются;
- при отсутствии сценария выводится конкретное пояснение о пробеле, а не пустая заглушка;
- ограничения: editorial_limitations → строка «Ограничения:» → catalog.limitations;
- одинаковые audit_notes и ограничения не дублируются в основном блоке;
- служебные сегменты «Часть N:» / «ЧN:» убраны из основного текста представления,
  а полный исходный текст оставлен в раскрываемых заметках; исходные данные не очищаются;
- основания точечного уточнения OpenRefine показаны со ссылками.

Проверки: unit-тест сохранности и идемпотентности точечного исправления; JS-проверки
дубля, сохранения служебного оригинала, fallback сценария и его оговорок, содержимого
OpenRefine и прежних страниц/фильтров. Визуальная проверка в браузере отдельно не
проводилась. Редакционные пробелы остальных проектов не заполнены предположениями.
Итог: 53 unit-теста и JavaScript smoke прошли; валидатор — 0 ошибок и 308 прежних
предупреждений. Повторный запуск исправления возвращает Changed: [].

```powershell
python tools/correct_openrefine.py
python -m unittest discover -s tests -v
node tests/ui_smoke.cjs
python tools/watch_pipeline.py validate
```

Генератор точечного исправления по умолчанию только показывает изменяемые файлы;
--write применяет их локально. Повторный запуск не меняет поля. Публикация и push
требуют отдельного решения пользователя.
