# Проверка качества конвейера — 23 октября 2026

Проверяется предотвращение ошибочной публикации, а не количество карточек. Исследовательские сведения, каталог и дайджест этим исправлением не изменяются. Четыре находки из приложенного текста не добавлены: в нём отсутствуют точные URL, сохранённые ответы и связанные с ними одобрения; первоисточники этих находок в этом аудите не исследовались.

## Подтверждённые пробелы и исправления

1. Отсутствующий журнал исключений считался пустым, поэтому удаление журнала позволяло обойти запрет. Валидатор теперь сравнивает защищённые записи с Git HEAD в настоящем checkout; проверка публикации сравнивает подготовленный снимок с явно выбранным доверенным коммитом. Записи журналов и прежние доказательства нельзя удалить или переписать; новые записи допускаются добавлением.
2. URL и ручной статус approved не требовали сохранённых первоисточников. Для новых одобрений обязательны source_checks с полным покрытием source_urls: сохранённый JSON-ответ с содержимым, URL, временем получения, HTTP 200, SHA-256 файла и verified_scope. Доказательство должно находиться внутри data/evidence, время проверки — между обнаружением и одобрением. Будущие одобрения блокируются. Проверено, заявлено авторами и независимо испытано теперь должны быть раздельными непустыми полями claims_vs_verified.
3. Проверка событий завершалась раньше сверки ledger, если из всех опубликованных представлений убрать события. Теперь сохранившийся ledger выявляет потерю проекций.
4. Доказательства могли измениться после dry-run, поскольку не входили в зависимости плана. Их байты, журнал исключений и перепроверки теперь входят в before и хеш плана; изменение до write блокируется. При проверке временного снимка доступны те же доказательства, что и в реальном checkout.
5. Перепроверка существования репозитория принимала дату из будущего; это блокируется. Повреждённый журнал завершается ошибкой, а не обходом или необработанным AttributeError.

Историческое одобренное событие HTRflow не переписывается: его прежний content hash и SHA-256 существующего артефакта закреплены явно. Удаление/подмена этого файла теперь блокирует валидацию. Это старый артефакт статической проверки, не новый снимок всех HTTP-ответов; его происхождение не переименовано в независимый benchmark.

## Воспроизведение

`python tools/verify_guard_regressions.py --base b0b1f2f --write` исполняет известные версии собственных проверок из указанного Git-коммита на временных синтетических данных. Три сценария подтверждают прежний допуск и новый отказ: исчезновение журнала исключений, approved URL без сохранённого содержимого и потеря всех проекций событий при сохранившемся ledger. Результат: reports/pipeline-guard-regressions.json.

Новые регрессионные тесты дополнительно проверяют подменённые/потерянные снимки, другой URL или HTTP 404 в доказательстве, пустое содержимое, выход за data/evidence, изменение после одобрения/плана, повреждённый журнал, отсутствие исторического доказательства и неразделённые заявления.

Проверка публикации конкретного подготовленного дерева:

```powershell
python tools/check_publication.py --base b0b1f2f
```

Команда не публикует: читает Git index, проверяет сохранность относительно доверенного коммита, ищет известные шаблоны секретов/запрещённые Actions и запускает валидатор, unit-тесты и UI smoke именно на подготовленном снимке. При --base список изменённых файлов берётся из diff к этому коммиту, а не из устаревшего манифеста первоначальной публикации. Доверенный base нужно выбирать из уже рассмотренной версии; произвольный более поздний коммит не является независимым основанием доверия.

## Формат новых источников

В source_checks кандидата указываются url, checked_at, evidence_file, sha256 и verified_scope. Файл evidence_file содержит url, checked_at, http_status и непустой content с полученным текстом источника. После получения всех источников редактор формирует раздельные claims_vs_verified и одобрение, связанное reviewed_content_hash со всем кандидатом. Исправление любого из этих полей требует нового одобрения.

## Граница гарантий

Итоговая проверка подготовленного Git index относительно b0b1f2f прошла: 74 unit-теста, UI smoke, 0 ошибок и 171 предупреждение валидатора; проверены 101 файл снимка, из них 14 изменённых. Известных шаблонов секретов, бинарных файлов и GitHub Actions не обнаружено. Это ограниченный поиск шаблонов, не исчерпывающий аудит секретов. Повторное воспроизведение старых обходов сохранено в машинном отчёте. Изменения исследовательских данных отсутствуют; исправление конвейера сохранено локально, публикация не выполнялась.

Это проверка целостности, согласованности и полноты записи проверки. SHA-256 обнаруживает изменение сохранённых байтов, но не доказывает истинность текста и не удостоверяет автора файла. Поле reviewer само по себе не аутентифицирует человека. Автор с правом менять код, историю Git и все доказательства согласованно способен обойти локальные проверки; прямой git push не перехватывается автоматически. Подписи/защита ветки или независимый контролёр публикации здесь не настроены; GitHub Actions не добавлялись.

Контрактные тесты не подтверждают доступность Gallica, качество HTR или правильность генеалогических выводов. Эти вопросы требуют отдельных проверок первоисточников и испытаний. Проверка браузером в этом аудите не выполнялась.
