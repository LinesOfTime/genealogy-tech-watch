# Новые правила обнаружения: genealogy × agent skills

Дата: 2026-10-26. Это предложение к включению в основной регламент; правила не считаются действующим автоматическим расписанием до реализации и тестов.

## Обязательные поисковые корзины
- Классические: genealogy, family history, GEDCOM, Gramps, family tree, archive digitization, parish register, OCR, HTR.
- Агентные: agent skills, codex, claude-code, kinship, ancestry research, evidence-first, historical research, records linkage, archival agents.
- Региональные: Russian Empire, USSR, ex-USSR, Soviet archives, метрические книги, родословная, генеалогия, архив, ревизские сказки.
- Комбинировать понятия: (genealogy OR kinship OR family-history) AND (agent OR skill OR codex OR LLM); словари используются для генерации GitHub Search запросов и не гарантируют полноту выдачи.

## Discovery отдельно от мониторинга известных репозиториев
1. Искать newly created и recently updated за 7 дней с повторной проверкой окна 14 и 30 дней; хранить last_successful_scan и scanned_window.
2. Собирать кандидатов не только из топа stars, но и из новых/малых репозиториев, смежных направлений и профильных дайджестов. Записывать точный поисковый запрос, дату, страницу результатов, число результатов и API-ограничения.
3. Канонизировать owner/repo через GitHub API, учитывая переименование и редиректы. Не создавать вымышленные репозитории или «дубликаты» при различии регистра.
4. Сопоставлять с catalog.json, digest.json, data/discoveries.jsonl и alias-реестром. Новая находка не равнозначна новому релизу.
5. Для каждого кандидата: README, SKILL.md, ключевые скрипты/тесты, LICENSE, дата создания, commit SHA; отдельно author claims, verified code/docs и independent tests.
6. Ранжировать по применимости к генеалогии (включая методологию доказательств), России, архивной работе и смежным agent pipelines; stars и возраст не должны быть отсечкой.
7. Ведущий пример регрессионной проверки обнаружения: DenisSergeevitch/ex-ussr-kinship-research — должен попадать в список кандидатов при воспроизведении поиска с датой 2026-10-26.
8. При каждом выпуске показывать coverage report: запросы, просмотренные проекты, новые кандидаты, отклонённые с причиной, дубликаты, ошибки API, что осталось непроверенным.

## Публикация
- Новые кандидаты проходят действующий DISCOVERY_WORKFLOW.md: evidence → pending → конкретное редакционное утверждение → apply → tests → публикация.
- Не вставлять вручную данные в огромные embedded JSON внутри HTML и не менять status на approved без решения редактора.
- Ручной обзорный материал допустим отдельной страницей со статусом «обзор / не тестировался»; запись каталога и дайджеста оформлять через конвейер.
- Не вводить GitHub Actions и не накапливать артефакты Actions без отдельного разрешения; соблюдать действующий режим Pages main/docs.

## Приёмка
- Регрессионные тесты на текущий контрольный проект, на отрицательные примеры и на переименованные репозитории.
- Одинаковые результаты при повторном apply.
- Не изменены прежние приоритеты без доказательств.
- Нет фиктивных timestamps, голословных заявлений о тестах или автоматических скачиваний чужих пользовательских данных.
