# Этап D: предварительный diff и локальное применение

## Безопасный запуск

```powershell
Set-Location D:\AI\genealogy-tech-watch-git
python tools/watch_pipeline.py review --report
python tools/watch_pipeline.py apply --approved-only --edition-date 2026-10-22 --dry-run
# После просмотра diff подставить plan_hash из предыдущего вывода:
python tools/watch_pipeline.py apply --approved-only --edition-date 2026-10-22 --write --expect-plan HASH
python tools/watch_pipeline.py validate
python -m unittest discover -s tests -v
git diff --check
git diff --stat
git status --short
```

Дата выпуска задаётся явно и не зависит от часового пояса компьютера.
Без `--write` команда только строит план. `--write` требует `--expect-plan`;
изменение плана после просмотра блокирует запись. Перед записью дополнительно
проверяются исходные байты файлов. Сеть, commit и push не вызываются.

Реальный запуск на пустом `data/discoveries.jsonl` от 2026-10-22:
`mode: dry-run, events: [], skipped: [], files: [], plan_hash: null`.
Никаких находок, первоисточников или человеческих утверждений для демонстрации
не выдумывали. Применение непустого события проверено на синтетических копиях,
а сквозной прогон с реальной подтверждённой находкой остаётся открытым.

## Что меняет apply

Для существующей карточки добавляется событие в `history` и в
`docs/research.json → <ключ карточки> → watch_events`. Старые поля, guide_excerpt,
редакционные тексты, приоритеты и прежняя история сохраняются. Изменения лицензии
и возможностей отражаются в новом событии, старые значения автоматически не
переписываются. Это консервативное добавление истории; произвольные патчи полей
не поддерживаются. История доступна существующему рендереру project.html.

Новый проект получает карточку с явными неизвестными применимостью, ограничениями,
приоритетом и тестированием; описание берётся из утверждённой дельты. Сведения о
лицензии сохраняются с источниками и без заявления о независимом испытании.
Если совпало несколько research-ключей или сопоставление не соответствует name,
применение блокируется до ручного согласования. Перенос не переименовывает старые
карточки и не удаляет исследования.

Событие хранит discovery_id, date, change, previous_state, new_state,
significance_reason, source_urls, url, claims_vs_verified, risks, license,
license_evidence, review_status, reviewer, reviewed_at, reviewed_content_hash.

Для `publish` добавляется запись items с прежними обязательными полями и
обратно совместимыми полями event_date, significance_reason, review_status,
reviewer, reviewed_at, discovery_id, source_urls, research_link, previous_state,
new_state. Существующий выпуск за дату дополняется; его заголовок и summary
сохраняются. Иначе создаётся один новый выпуск с утверждёнными событиями.
Для `research_only` карточки и история обновляются без нового выпуска и без
изменения байтов корневого digest.json. watch/reject/pending не применяются.
При отсутствии подходящих событий ни один файл не меняется.

`data/applied-events.json` создаётся при первом применении и хранит
`discovery_id → content_hash`. Тот же ID с тем же содержимым пропускается;
изменённое ранее применённое событие блокируется. Журнал кандидатов не переписывается.
Несколько готовых событий одной карточки в одном запуске блокируются: их нужно
обработать раздельно, оставляя уже применённые записи в журнале.

Финальная проверка перед публикацией усилена: новые события сверяются между
каталогом, research, дайджестом, журналом и реестром хешей; потеря даты, источника,
утверждения или записи блокирует validate. Применённые записи из --input
сохраняются в основной журнал с сохранением остальных находок. Конфликт содержания
с существующей записью журнала блокирует применение до согласования.

## Синхронизация и запись

План содержит корневые каталог/дайджест, их docs-копии, два HTML seed, research и
реестр применений. Полный предлагаемый статический снимок проходит валидатор во
временной папке до записи. При ошибках запись не начинается.

`python tools/sync_data.py` теперь синхронизирует также docs/catalog.json и
docs/digest.json. HTML за пределами seed сохраняется. Все замены готовятся до
первой записи; повторная синхронизация согласованного снимка ничего не пишет.
Проверки страниц/фильтров в браузере и устранение кэша относятся к этапу E.

При обычной ошибке замены файлов выполняется откат уже записанного содержимого.
Это не транзакция файловой системы при отключении питания или аварийном завершении
процесса: после такого сбоя необходимо проверить validate и Git diff, восстановить
согласованный снимок и только затем повторить запуск. Откат также зависит от
доступности диска. Не запускать параллельно несколько пишущих процессов.

после явного разрешения подготовить commit только из согласованных файлов и push.
`git add .` здесь небезопасен: в рабочей копии остаются посторонние исходные файлы.

## Начальный расширенный профиль новых проектов

Поле `initialize_research_profile=true` вместе с проверенным `catalog_profile` создаёт редакционные поля нового исследования, лицензию, зрелость и происхождение по тому же утверждённому событию. Флаг и профиль входят в content_hash. Существующие карточки не перезаписываются. Валидатор сверяет начальные поля и происхождение с журналом; самостоятельное изменение текста блокирует публикацию. Статус независимого тестирования остаётся «Не тестировалось», применимость для России не выводится автоматически.
