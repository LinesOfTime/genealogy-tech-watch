# Публикация Watch одним подтверждением

Этот сценарий дополняет `tools/watch.py` и не меняет требования к проверке первоисточников.

1. Исследователь формирует `candidates.jsonl` с `review_status=pending`; импорт: `python tools/watch.py ingest candidates.jsonl`.
2. Редактор утверждает конкретный пакет по `DISCOVERY_WORKFLOW.md`; технические review-поля и content_hash заполняются существующим процессом, без имитации одобрения.
3. На чистой отдельной ветке выполнить `python tools/watch.py prepare --date YYYY-MM-DD`; проверить события, diff и `plan_hash`.
4. **После явного утверждения** выполнить одну команду:

```powershell
python tools/watch_publish_pr.py --date YYYY-MM-DD --expect-plan ПЛАН_HASH --execute
```

Команда проверяет чистоту ветки, вызывает штатный apply и локальные тесты, ограничивает изменяемые пути, делает commit/push и создаёт PR через `gh`. Требуются установленные `git`, `gh` и авторизация `gh auth login`. Если PR для ветки существует, повторно не создаёт.

**Публикация сайта** наступает только после проверки и merge PR и проверки GitHub Pages. Скрипт намеренно не делает auto-merge, не подделывает утверждение и не добавляет GitHub Actions. Полностью автоматическое слияние потребует отдельного согласованного правила и дополнительной проверки безопасности.

При сбое после локального применения проверить `git diff`, `git status` и результаты тестов перед повторным запуском; не считать операцию атомарной.
