# Подбор проектов по задаче

Добавлена docs/tasks.html с семью задачами: транскрибирование/OCR/HTR, получение
сканов, сопоставление людей/записей, исторические места, исследование с источниками,
GEDCOM/визуализация и подключение ИИ. На страницу ведут каталог, дайджест и карточка.

Результаты показывают основание подбора с исходным текстом и полем, ограничения,
существующий статус испытаний, редакционную применимость для России, дальнейшую
проверку и переход к полному исследованию. Доступны фильтр по основанию и поиск.
Порядок по названию, редакционные P1/P2/P3 не участвуют в отборе или ранжировании.

Это начальная лексическая навигация по сохранённым редакционным материалам, а не
экспертная рекомендация по результатам новых испытаний. Статус editorial означает
«описано в редакционных материалах», candidate — возможный кандидат. Статус
«испытано на сценарии» не присваивается автоматически: для него нужны отдельные
документированные результаты, которых эта миграция не создаёт.

Основания формируются по description/use_case/components и
editorial_summary/editorial_use_case/строкам назначения и сценария guide_excerpt.
Название проекта, project_type, лицензия, оценка для России и раздел ограничений
не используются как положительное основание соответствия. Компоненты без сценария
дают только candidate. Слова кандидат/возможно/может/потенциально/вероятно сохраняются
и снижают результат до candidate; даже editorial не означает подтверждения функций.

Лексический поиск может пропустить синонимы и давать широкие совпадения. Само
упоминание OCR или GEDCOM не гарантирует выполнение любой части такой задачи:
обязательно читать приведённое основание и исследование. Отсутствие проекта в
результатах не доказывает отсутствия соответствующей возможности.

На текущих материалах: 134 соответствия задачам для 102 проектов. Для остальных
62 проекты остаются в полном каталоге, но подходящих лексических оснований нет.
Каталог, research, история, приоритеты и дайджест JSON не изменяются.
docs/task-matches.json хранится отдельно: задачи, соответствия, цитаты исходных
полей и хеш исходных каталога/исследований. Это производная навигация, не новая
исследовательская карточка. После изменения исходных данных её надо пересобрать;
тест проверяет полное соответствие с актуальными источниками.

```powershell
Set-Location D:\AI\genealogy-tech-watch-git
python tools/build_task_matches.py
python tools/build_task_matches.py --write
python -m unittest discover -s tests -v
node tests/ui_smoke.cjs
python tools/watch_pipeline.py validate
python -m http.server 8000 --bind 127.0.0.1
# http://127.0.0.1:8000/docs/tasks.html
```

По умолчанию генератор показывает число проектов/соответствий и необходимость
обновления. --write записывает только производный файл; повторный запуск не пишет
его при совпадении. Воспроизводимость и сохранность входных объектов покрыты тестами.

Файлы: tools/build_task_matches.py, docs/tasks.html, docs/tasks-ui.js,
docs/task-matches.json, tests/test_task_matches.py, tests/ui_smoke.cjs, ссылки в
трёх существующих HTML-страницах и этот отчёт. GitHub Actions и внешнее расписание
не добавлены. Публикация требует отдельного разрешения.

Проверки: 52 unit-теста прошли, включая порядок статусов кандидата, сохранность
оговорок/входных данных, отсутствие отбора по названию/типу/ограничениям и полное
совпадение производного JSON с источниками. JavaScript smoke проверил все семь
задач, число результатов, фильтр кандидатов и пустой поиск. Синтаксис tasks-ui.js
проверен Node. Валидатор: 0 ошибок, 308 прежних предупреждений; git diff --check
прошёл. Визуальная проверка в браузере отдельно не проводилась. Повторная генерация
возвращает changed: false. Каталог, research и digest JSON в Git diff не изменены.
