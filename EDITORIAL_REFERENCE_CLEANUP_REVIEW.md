## Проверка существования репозиториев

Добавлен отдельный онлайн-аудит `python tools/audit_repositories.py --all --write`. Проверено 162 GitHub-адреса из 163 записей: 160 HTTP 200, два HTTP 404. Одна запись ведёт к профилю GitHub, а не к URL репозитория; она явно отмечена как not_a_github_repository_url. Сетевые ошибки, HTTP 403/429 и другие неопределённые ответы не превращаются в «репозиторий не существует».

Два новых сигнала 404 — komura-shoan/iiif-downloader и прежний адрес scripta/escriptorium — вынесены в reports/repository-existence.json и предупреждения валидатора repository_not_found. Они требуют отдельного редакционного решения; автоматически удалять или менять URL других проектов эта правка не стала.

Валидатор блокирует возврат ранее отклонённой ссылки в каталог, research, дайджест и исходящие HTML-ссылки, включая варианты регистра, .git и ссылки на разделы репозитория. Конвейер apply проверяет тот же запрет до формирования файлов. Снять запрет может только более поздняя запись успешной проверки GitHub API: HTTP 200, совпадающее full_name и положительный id репозитория, сохранённый ответ и его SHA-256. Команда проверки: `python tools/audit_repositories.py --url https://github.com/OWNER/REPO --write`. Сам успешный ответ не добавляет карточку обратно автоматически.

Добавлено правило service_note_in_content, блокирующее возврат служебных пометок в пользовательские поля. Миграция `python tools/remove_invalid_reference.py` по умолчанию показывает план, запись требует --write; повторный запуск не меняет файлы.
