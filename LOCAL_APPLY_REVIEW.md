## Локальная проверка и публикация PowerShell

```powershell
Set-Location D:\AI\genealogy-tech-watch-git
python tools/watch_pipeline.py validate
python -m unittest discover -s tests -v
node tests/ui_smoke.cjs
python tools/watch_pipeline.py apply --approved-only --edition-date 2026-10-22 --dry-run
python tools/verify_real_event.py --discovery-id github:ai-riksarkivet/htrflow-batch:d087c1ec02417c73e4061b8a54fc44627424d876 --report reports/local-recheck.json
git diff --check
git status --short
git diff --stat
```

Повторная проверка без baseline проверяет согласованность и однократность события;
не повторяет сравнение всех полей с утраченным временным снимком. Исходное сравнение
сохранено в local-apply-result.json; для новой проверки используется отдельный файл.

Перед публикацией нужно отдельно выбрать согласованные файлы, проверить staged
diff и получить явное разрешение push. Не использовать git add .: в рабочей копии
есть посторонние резервные файлы и скрипты. После ручного выбора файлов:

```powershell
git diff --cached --check
git diff --cached --stat
git diff --cached
# Только после явного разрешения публикации:
git commit -m "Add reviewed genealogy watch pipeline and verified reading-order event"
git push origin main
```
